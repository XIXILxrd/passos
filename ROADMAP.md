# Passos

Цель проекта — практика Go на примере локального кроссплатформенного CLI-менеджера паролей. После каждой подзадачи автор приносит свою реализацию на ревью.

Статусы задач — «В плане», «В работе», «Готово».

| № | Подзадача | Критерий готовности | Статус |
|---|---|---|---|
| 1 | Настроить кросс-сборку и сборку в Docker. Сделать `cmd/passos` исполняемым пакетом, добавить команды сборки и `Dockerfile`. | Бинарники собираются для Windows, Linux и macOS на `amd64` и `arm64`. Через Docker их можно собрать без локальной установки Go. Бинарник для текущей ОС запускается. | В плане |
| 2 | Добавить каркас CLI с `--help` и обработкой неизвестных команд. | Справка выводится с кодом 0. Неизвестная команда возвращает ненулевой код и понятную ошибку. | В плане |
| 3 | Добавить записи в памяти. Реализовать `Entry`, `Add` и `List`. | У одного сервиса могут быть разные логины. Дубликат пары «сервис + логин» отклоняется. Изменение результата `List` не влияет на хранилище. | В плане |
| 4 | Реализовать `Update` по паре «сервис + логин». | Меняется пароль только выбранной записи. При отсутствии записи возвращается ошибка. | В плане |
| 5 | Зашифровать хранилище. Сериализовать записи и добавить версию формата. | Записи восстанавливаются с правильным мастер-паролем. Неверный пароль и повреждённые данные приводят к ошибке. | В плане |
| 6 | Реализовать создание, загрузку и сохранение хранилища через временный файл. | Записи переживают перезапуск. Повторное создание и сбой до замены файла оставляют существующее хранилище целым. | В плане |
| 7 | Подключить `init` и `add` со скрытым вводом секретов. | Хранилище можно создать и наполнить отдельными запусками CLI. `init` запрашивает подтверждение мастер-пароля. | В плане |
| 8 | Подключить `update` и `list`. Пройти полный сценарий на Windows, Linux и macOS. | После разблокировки `list` показывает сервисы и логины, а `list --show-passwords` включает пароли. Обновлённый пароль виден после перезапуска. На каждой ОС проверены скрытый ввод и сохранение файла. | В плане |
